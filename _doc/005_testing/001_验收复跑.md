## 1. 验收项：四个能力仓各自的引擎行为

### 1.1 z-sense —— 敏感识别与分类分级

| 验收项 | 落点（用例） | 读数（实测） |
|---|---|---|
| 形状 + 语义双闸 | `SenseServiceTest` | 校验位错的身份证**不命中**；手机号号段校验生效；银行卡 Luhn 生效 |
| 分类 × 分级正交 | 同上 | 命中报 `category=ID_CARD` + `level=L3`，不是笛卡尔积 |
| 命中必带位置 | 同上 | 命中带 `[start, end)` 偏移 |
| 重叠消解 | 同上 | 同位置多规则命中 ⇒ 级别高者留、同级先注册者留 ⇒ **幂等** |
| 弱规则收紧 | 同上 | 「手机」「卡号」「都是本人」**不判为人名** |
| 普通文本不误伤 | 同上 | 零命中 |
| 端点可路由 | `SenseApiE2ETest` | `POST /z-team/api/sense/detect` 真 HTTP → 报出类别/分级/位置 |

### 1.2 z-mask —— 脱敏与遮蔽

| 验收项 | 落点（用例） | 读数（实测） |
|---|---|---|
| 识别一次脱敏一次 | `MaskServiceTest` | 脱敏**以 z-sense 命中为输入**，不重扫 |
| **按命中脱敏重载** | `MaskByHitsTest` | 传入已有命中列表 ⇒ **识别器调用次数 = 0**（计数验）；越界命中跳过、重叠按 z-sense 同算法消解、长度契约破坏 ⇒ 退回自识别 |
| minLevel 贯穿每一档 | 同上 | minLevel=L4 的策略**不脱敏 L3 数据** |
| 无策略 ⇒ 不脱敏 | 同上 | 未配策略的类别保持原样 |
| 倒序替换 | 同上 | 多处命中 ⇒ **位置不错位**，明细排回升序 |
| 四种脱敏 | 同上 | FULL / MASK / HASH / ENCRYPT 各自生效 |
| 绝不返回原文 | 同上 | HASH 算法不可用 ⇒ 退化全遮蔽（**不退回原文**） |
| 端点可路由 | `MaskApiE2ETest` | `POST /z-team/api/mask/apply` 真 HTTP → 报出脱敏明细 |

### 1.3 z-watermark —— 三种水印技术

| 验收项 | 落点（用例） | 读数（实测） |
|---|---|---|
| 显式文字水印 | `WatermarkServiceTest` | 首尾各插一行；**幂等不叠加**；可提取回载荷 |
| 图片隐写 | 同上 | 往返可提取回 traceId；**平均像素差 ≤ 1**（视觉无感）；PNG 硬约束 |
| 盲水印 | 同上 | 往返可提取回 traceId；**词内容不变**（只改空格宽度） |
| 容量不足不嵌入 | 同上 | 短段落 ⇒ **原样返回**（不嵌半截水印） |
| 载荷往返 | 同上 | 含空字段（`-` 占位）仍可往返 |
| 端点可路由 | `WatermarkApiE2ETest` | `POST /z-team/api/watermark/embed`（自带自检）+ `/extract` |

> ⚠ **盲水印容量是设计约束**：traceId 约 13 字符时需 **约 64 个词间隔**（约 65 词）。
> 短段落打不上是**正常行为**，不是 bug。

### 1.4 z-audit —— 哈希链

| 验收项 | 落点（用例） | 读数（实测） |
|---|---|---|
| 链头哨兵 | `AuditServiceTest` | 首条 `prevHash` = 全零 64 位 |
| 链式相连 | 同上 | 后一条 `prevHash` = 前一条 `hash` |
| **篡改检出** | 同上 + `AuditEventApiE2ETest` | 改内容 ⇒ 检出「哈希不匹配」；**绕过应用直接改库**同样检出 |
| **删除检出** | 同上 | 删中间一条 ⇒ 检出链断 |
| 尾部截断 | `ChainAnchorServiceTest` + `ChainAnchorApiE2ETest` | **M2 起可检出**（靠外部锚定）：绕过应用直接 DELETE 库删链尾 ⇒ 检出 |
| 留存期分档 | 同上 | 出域动作 1095 天 / 高危 730 天 / 默认 180 天 |
| DDL 幂等 | `AuditEventApiE2ETest` | 建三遍不报错、不改结构 |
| 端点可路由 | 同上 | `POST/GET /z-team/api/audit/events`、`/chain/verify`、`/chain/latest` |

> ⚠ **web 层测试从生产 DDL 脚本读表结构**（`AuditTestSchema`），不内嵌第二份 DDL
> —— 内嵌一份必然漂移 ⇒ 测试全绿但生产炸。

## 2. 验收项：z-biz-security 编排层

| 验收项 | 落点（用例） | 读数（实测） |
|---|---|---|
| 场景 → 策略 | `SecurityPipelineTest` + `SecurityPipelineApiE2ETest` | 5 个内置场景；**未登记场景走兜底**（不失败） |
| 四段流水线 | `SecurityPipelineTest` | 识别 + 脱敏 + 水印 + 审计，按策略的阶段序列执行 |
| **拦截在脱敏前** | 同上 | 命中 ≥ 阈值 ⇒ `BLOCKED`，**不返回原文** |
| 阈值区分 L3/L4 | 同上 | L3 身份证 / L4 银行卡的拦截行为分别验证 |
| null 阈值不拦 | 同上 | `blockThreshold=null` ⇒ 永不拦 |
| 拦截也留痕 | 同上 | 审计结果 = `DENIED` |
| 不跑审计 ⇒ 无留痕 | 同上 | 阶段序列不含 AUDIT ⇒ 台账为空 |
| 端点可路由 | `SecurityPipelineApiE2ETest` | `POST /z-team/api/biz/security/process`；**命中 ⇒ HTTP 403** |
| 策略查询 | 同上 | `GET /policies?scene=...` 报出阶段序列 / 水印类型 / 阈值 |
| **★ 只识别一次** | `SecurityPipelineSingleSenseTest` | 计数识别器验证：全文**只识别一次**；只跑 SENSE 也只一次；只跑 MASK ⇒ 退回自识别一次（不是零次）；**规则中途变化 ⇒ 拦截与脱敏仍同源** |
| **★ 策略台账** | `PolicyLedgerServiceTest` + `PolicyLedgerApiE2ETest` | 发布落库 + **热改立即生效**（不用发版）；**操作人/变更原因为空 ⇒ 400 且不落库**；一场景一版；**回滚以新版本号重发老内容、历史一条不丢**；台账全量查询（含原因/操作人）；停用；**重启后策略不丢**；**台账为空 ⇒ 播种内置 5 场景** |
| **★★ 台账读空不清空注册表** | `PolicyLedgerServiceTest` + `SecurityPipelineApiE2ETest` | 台账表不存在时**保留内置策略**（5 场景仍在）—— 否则全部降级 DEFAULT（阈值 L4）⇒ L3 敏感数据直接出域 |

## 3. 已知边界（M1 明确不做，不是 bug）

| 边界 | 影响 | 后续 |
|---|---|---|
| ~~**哈希链尾部截断查不出来**~~ | ~~最后几条被删无法在链内发现~~ | ✅ **M2 已解**：链头锚定落地，截断可检出 |

## 4. 生产执行清单（**人工动作**，自动化流水线不执行）

1. 在生产 `oc` 库执行 `z-audit/_doc/002_deploy/init.sql`（3 张表，幂等）
   与 `z-biz-security/_doc/002_deploy/init.sql`（1 张表，幂等）。
2. ⚠ 执行前确认目标库默认字符集是 `utf8mb4`。
3. ⚠ 脚本**不含** `CREATE INDEX`（MySQL 8.0 无 `CREATE INDEX IF NOT EXISTS` ⇒ 破坏幂等）；
   二级索引需求另开 `_doc/002_deploy/init/002_*.sql` 并**只执行一次**。
4. ⚠ **M1 老库必须补执行增量迁移** `z-audit/_doc/002_deploy/init/002_anchor_fingerprint.sql`
   （给已建的 `z_audit_chain_anchor` 补 `fingerprint` 列）。不执行 ⇒ 运行时报
   `Unknown column 'fingerprint'`（`CREATE TABLE IF NOT EXISTS` 不会给已建表加列）。
5. ⚠ **老锚点行 `fingerprint` 为空 ⇒ 校验判「不可信」⇒ 要求重新打锚**（故意设计）。
6. 四个 L3 能力仓（z-sense / z-mask / z-watermark / z-audit）**本轮不发 Central 制品**；
   z-biz-security 是内部件（`maven.deploy.skip=true`）。
7. ⚠ **锚点表建议独立库/独立账号**：锚点必须独立于链存在，否则删库的人能同时删锚点。
